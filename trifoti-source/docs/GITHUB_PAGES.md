# Публикация ТРИФОТИ на GitHub Pages

Публичный адрес: https://step3dlab.github.io/STEP_3D/trifoti/

В репозитории существуют два способа публикации: workflow `.github/workflows/pages.yml` загружает корень репозитория, а встроенная публикация GitHub Pages использует `main:/docs`. Поэтому одна и та же готовая сборка размещена в `trifoti/` и `docs/trifoti/`. Эти каталоги должны обновляться вместе. Папка `trifoti-source/` содержит исходники.

## Обновление

Из `trifoti-source/` выполните:

```sh
npm ci
npm run build:pages
```

Проверенная статическая сборка появится в `pages-dist/`. Замените ею содержимое двух выделенных каталогов портфолио: `../trifoti/` и `../docs/trifoti/`. Сохраните пустой файл `../docs/.nojekyll`, затем отправьте изменения в `main`. Другие файлы в `docs/` относятся к прежним страницам репозитория.

Ожидаемые настройки экспорта: `NEXT_PUBLIC_BASE_PATH=/STEP_3D/trifoti`, `NEXT_PUBLIC_SITE_ORIGIN=https://step3dlab.github.io` (это значения по умолчанию в скрипте).

Файл `.nojekyll` располагается в корне источника Pages (`docs/`) и позволяет публиковать готовые ресурсы Next.js, включая `_next`, без обработки Jekyll. См. [официальную инструкцию GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).

После публикации дождитесь завершения обеих задач Pages. Проверьте главную страницу, переключение всех трёх кадров в первом экране, прямую ссылку на кейс и открытие галереи. Статическая форма готовит сообщение для самостоятельной отправки через Telegram или почту; серверного сохранения заявок у этой версии нет.
