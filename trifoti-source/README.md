# ТРИФОТИ

Креативная студия Фёдора Паршина и Владимира Ганьшина: скульптура, арт-объекты, интерьерные композиции, авторские награды и объекты для сцены.

Это самостоятельный Site на основе предоставленного исходного сайта Step3D. Оригинальный Site и его база заявок не изменяются и не используются новым сайтом.

## Публичная часть

- `/` — авторская главная, избранные работы, интерактивные этапы, подбор параметров объекта, трёхшаговый бриф.
- `/projects` — галерея с поиском и фильтрами.
- `/cases/[slug]` — 11 кейсов с реальными материалами команды, фотографиями, видео и статусом проекта.
- `/about` — студия и основатели.
- `/services` и `/services/[slug]` — направления работы и требования к исходным материалам.
- `/business` — сотрудничество с архитекторами, дизайнерами, девелоперами, культурными площадками и брендами.
- `/privacy`, `/consent`, `/offer`, `/requisites` — действующий оператор Step3D; бренд ТРИФОТИ не объявлен отдельным юридическим лицом.
- `/status` — состояние заявки по персональному номеру и токену, без контактных данных.

## Контент и авторство

Портфолио содержит предшествующий опыт Фёдора Паршина и команды Step3D. Авторская скульптура Паршина подписана отдельно; остальные работы представлены как портфолио команды с подтверждённым вкладом. RED7 — проектная разработка/визуализация, не фотография реализованного объекта. Фотографии клиентов и портреты не генерировались. Числа в исторических кейсах не являются текущими тарифами. Стоимость нового объекта рассчитывается индивидуально.

При добавлении работы нужны: название, автор и роль команды, год, место, статус (реализована/концепция), задача, решение, результат, 3–8 разрешённых к публикации фотографий, при необходимости видео. Не публиковать адрес частного клиента, чертежи или другие конфиденциальные материалы без согласования.

Основные файлы контента: `app/case-data.ts`, `app/service-data.ts`; категории и связи кейсов — `app/project-routing.ts`. Визуальные стили: `app/trifoti.css`. Бренд: `app/components/Brand.tsx`. Изображения: `public/images/`.

## Заявки и доступ

`POST /api/leads` сохраняет обращение в отдельную D1-базу и возвращает номер `TFT-…` и секретный токен. `/api/uploads` прикрепляет до пяти файлов по 25 МБ к этой заявке в R2. Закрытый `/leads` показывает обращения, статусы, файлы, продажи и аналитику. CSV доступен владельцу.

Авторизация кабинета использует доверенную identity хостинга и точное совпадение email с `TRIFOTI_OWNER_EMAIL`. Иной пользователь или анонимный запрос не получают административный доступ. Резервный ключ `LEADS_ADMIN_KEY` допускается только длиной от 24 символов; в исходниках ключей нет.

Настроено: `TRIFOTI_OWNER_EMAIL=projects.step3d@gmail.com`.

Telegram-бот, webhook и внешняя аналитика необязательны и по умолчанию не подключены. Заявка сохраняется и без них. На странице подтверждения честно показано, было ли отправлено уведомление, и доступны готовые ссылки для продолжения разговора. Тестовые заявки создаются только в локальном окружении.

## Автоматический поиск возможностей

Отдельная задача ChatGPT «Заказы для ТРИФОТИ» создана 21 октября 2026 года. Проверка — ежедневно утром по Москве, начиная с 22 октября. Начальный приоритет: Москва/МО и заказы по России, подходящие для изготовления с доставкой или согласованным монтажом. Направления: скульптура, интерьерные панно, арт-объекты, авторские награды, выставочные и сценические объекты.

Мониторинг ищет действующие объявления в открытых источниках и проверяет первичную карточку, заказчика, сроки, бюджет и ограничения. До пяти новых подходящих возможностей поступают в разговор ChatGPT. Конкурсы и резиденции отделены от коммерческих заказов. При отсутствии подтверждённых новых возможностей уведомление не отправляется. Автоматические отклики, регистрация на площадках и отправка сообщений заказчикам не включены. Этот мониторинг не записывает найденные объявления в базу входящих заявок сайта.

## Разработка и публикация

Стек: React / Vinext / Vite, Worker, Drizzle, D1, R2. Версии зафиксированы в `package-lock.json`.

```bash
npm run install:ci
npx tsc --noEmit
npm run build
node --experimental-strip-types --test tests/admin-auth.test.mjs
node --test tests/sales.test.mjs
```

Для управляемого локального просмотра используется `sites-preview start <путь-к-проекту>`. После сборки миграции `drizzle/0000_*.sql`…`0003_*.sql` применяются последовательно к пустой локальной D1 с `--local --persist-to .wrangler/state`; повторное ручное применение не требуется. Production-миграции выполняет Sites при публикации. Обработчики запросов не создают и не изменяют схему БД.

Публикация — штатным Sites workflow с сохранением исходников, сборкой и архивом той же ревизии. Проект определяется `.openai/hosting.json`. Токены Git передаются helper только через скрытый stdin, не сохраняются в файлы. Новая версия публикуется с приватным доступом владельца; открытый доступ и собственный домен настраиваются отдельно.

## Проверено при создании

- Сборка Worker и клиентской части; проверка TypeScript.
- Desktop, телефон 390 px и планшет 768 px; мобильное меню, фильтр галереи, выбор проекта и этапов.
- Передача конфигурации в бриф; локальное сохранение заявки и открытие её статуса.
- Изолированные проверки базы/вложений/статусов, правильного владельца, чужой identity, анонимного доступа и неверных токенов.

Внешние сообщения и реальные заявки заказчикам при проверке не отправлялись.


## Два раунда экспертной доработки

21 октября 2026 года проект прошёл две независимые рецензии в ролях арт-директора/UX и продюсера студии, затем два раунда внедрения. Подробности и ограничения проверки: `docs/REVIEW.md`.

В каталоге можно собрать до трёх реальных проектов в подборку и перенести их в бриф. Подборка хранится только в состоянии страницы; контакты в URL не записываются. Выбранные ориентиры передаются в бриф названиями и ссылками, отдельно от свободного комментария. Повторное применение конфигуратора заменяет прежние параметры.

## Версия на GitHub

- Публичное портфолио размещается в `STEP3DLab/STEP_3D`, каталог `trifoti/`.
- Исходники этого проекта — рядом, в `trifoti-source/`.
- `npm run build:pages` создаёт `pages-dist/`; скопируйте его содержимое в `trifoti/` для следующей публикации. Действующий workflow репозитория публикует всю статическую витрину при push в main.
- В этой версии бриф подготавливается в браузере. Посетитель сам отправляет текст через Telegram или почту, либо копирует/скачивает его. Файлы прикладываются к сообщению или передаются ссылкой.
- Кабинет, база заявок, загрузка файлов и персональные статусы работают только в полной серверной версии Sites. Статическая версия их не имитирует.
- Две сборки используют общие реальные материалы и локальные лицензированные шрифты. Настройки пути и различия документированы в `scripts/README-pages.md`.

При самостоятельном переносе backend за пределы Sites нельзя доверять входящему заголовку `oai-authenticated-user-email` от произвольного клиента: нужна собственная проверяемая авторизация или сохранение доверенного шлюза Sites. Публичные параметры статической сборки не содержат секретов.
