# Фокус при сокращении подборки до одного кадра

Исходная версия: `3bf815c74f94b3801a8ad25a7690b12e0965922e`.

## Подтверждённая ошибка

В опубликованном Chrome открыт `meeting.html#show/gesture/0`, затем в той же вкладке `#show/gesture,pink/0`. При фокусе на кнопке «Следующий кадр» возврат браузером Назад отключал обе кнопки листания и сбрасывал `document.activeElement` на `BODY`. Отдельно воспроизведено и для кнопки «Предыдущий кадр».

## Исправление

- Отрисовка запоминает, находился ли фокус на кнопке, которая станет недоступна. В этом случае после обновления она возвращает фокус на существующую область текущего кадра с `preventScroll`.
- При нескольких кадрах фокус на кнопках листания остаётся на месте. Доступные элементы, выход, выбор работы и фокус вне показа не перехватываются.
- Используется прежний механизм восстановления фокуса. Новых таймеров, событий, хранилищ или сетевых запросов нет. Обновлён только параметр версии meeting.js.
- Дизайн, медиа, атрибуция, обычное листание, маршруты, медведь и бриф не меняются.

## Проверки до публикации

- Шесть новых проверок: две кнопки × два события (`hashchange`/`popstate`), плюс сохранение фокуса доступных элементов при обоих событиях. Четыре регрессии падали на исходном коде. Тестовая модель учитывает нативную потерю фокуса при отключении кнопки.
- Те же сценарии проверяют повторные события без замены вручную загруженного видео и возврат к нескольким кадрам. Старые тесты сохранения фокуса дополнены кнопкой «Предыдущий кадр».
- `npm run check`: 754/754. Отдельная warm-версия: 16/16. Фокусные тесты ресурсов: 59/59.
- 180 файлов dist совпадают с обеими публичными копиями. `git diff --check` без замечаний.

## Границы проверки

Автотесты используют модель DOM; исходная ошибка подтверждена нативно в Chrome. Исправленная публичная версия проверяется после развёртывания, результат сообщается отдельно. Физические телефоны, Safari, Firefox и скринридеры в этом цикле не проверяются.
